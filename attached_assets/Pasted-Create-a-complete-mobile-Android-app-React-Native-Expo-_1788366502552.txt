### Feature Requirements

**1. Government Alerts**
- Each alert card must show:
  - Title
  - Severity color badge (Red = Critical, Orange = High, Yellow = Moderate, Green = Low)
  - Time
  - Location
  - Full alert text
- Support mock data + ability to add new alerts
- Alerts tab shows a full scrollable list of all alerts

**2. AI Chatbot (offline-first style)**
- One AI assistant that can:
  - Answer any disaster-related questions
  - Generate safety tips and first-aid instructions
  - Translate alerts into other languages
- Make it feel like a local/offline model (Llama-style). For the prototype:
  - Use a clean chat interface
  - Pre-load a solid set of disaster knowledge responses
  - Add a note “Running in offline mode” and simulate local inference
  - Support both text and quick-action buttons (Safety Tips, First Aid, Translate Alert)

**3. Public Chat**
- Completely open public room (no login required for prototype)
- Real-time style messaging UI (even if messages are local/mock for now)
- Users can send text messages

**4. Private Chat (Person 1, Person 2, … Person n)**
- List of saved contacts on home screen
- Tapping a person opens a private chat screen
- Simple messaging interface

**5. Translator Tab**
- Text-only translator
- Support English + all major Indian languages (Hindi, Bengali, Tamil, Telugu, Marathi, Gujarati, Kannada, Malayalam, Punjabi, Odia, Urdu, Assamese, etc.)
- Simple UI: source language → target language → input box → Translate button → result

**6. Map Tab**
- Show:
  - User’s current location
  - Nearby shelters, hospitals, and relief camps (use mock markers)
  - Flood / cyclone / earthquake risk zones (colored overlays)
  - Live crowd-sourced markers (Safe / Danger) that users can add
- Offline maps support (at least cache the last viewed area and show a clear “Offline Mode” indicator)
- Use react-native-maps or a suitable Expo-compatible map library

**7. Weather / Forecaster box (top-right)**
- Fetch real weather data using a free API (OpenWeatherMap or similar)
- Show temperature + short condition for the user’s location
- Graceful fallback if no internet

**8. Search Bar**
- Search across alerts, contacts, and chat messages

**9. Blockchain + Offline Messaging Backend**
- Design an end-to-end architecture that uses blockchain principles for message integrity
- Support offline message transfer via Bluetooth (simulate with a clear “Bluetooth Mesh / Offline Mode” layer)
- Messages should be verifiable (hash + timestamp) even when offline
- When back online, sync to a simple blockchain-style ledger (can be a local simulated chain or a lightweight backend)
- Clearly show in the UI when the app is in “Offline Bluetooth Mode”
